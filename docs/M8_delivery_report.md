# M8 delivery report — evaluation, security, observability, and reliability

Date: 2026-10-31

Status: Complete; private-demo release approved

Scope: QR-001 through QR-015; EVAL-01 through EVAL-18; ADR-011, ADR-012, ADR-019,
ADR-028

## Outcome

M8 adds a strict, versioned qualification manifest and fixed command runner covering every
evaluation dimension. The runner accepts no commands from data, rejects repository path traversal,
strips live provider/model/tracing environment variables, uses `.test.env`, captures bounded
redacted output, and produces a machine-readable report. Core and full profiles distinguish
credential-free checks from browser and local Qdrant/Redis integrations.

The final automated candidate, regenerated by the M9 gate, passes with zero critical automated failures: 274 backend tests,
35 frontend tests, nine Chrome journeys, one real-Qdrant test, and one real-Redis/RedisVL test.
Backend coverage is 87.28%. Production dependency scans are clean after updating the locked
`pypdf` from 6.21.3 to 6.21.4 to remediate three denial-of-service advisories.

M8 also closes an observability defect found during review: response-cache RunEvents and metrics
were creating bounded outcome/policy/match fields that the central allow-lists then dropped. The
allow-lists now retain only the intended bounded cache dimensions; raw query, Session/Run
identifiers, cached answers, and unbounded reasons remain excluded. New tests cover 128 concurrent
RunEvents, 128 unique synthetic Sessions collapsing to one metric dimension set, and a sensitive
telemetry canary.

The selected-model review consumed the owner-approved ceiling of 24 `gpt-6.1-sol` requests
with retries disabled. It exercised current live routing and conditional synthesis, all six agents,
active Finance and Tax collections, claim/citation grounding, financial-safety cases, and exact and
semantic cache paths. The agent found no critical defect and recommended passing EVAL-01, EVAL-03,
EVAL-08, EVAL-10, EVAL-12, and EVAL-17. The review also exposed and fixed a mixed-context gate bug:
authorized Portfolio, Market, Goal, and News context references are now validated together while
only the Portfolio subset becomes active Portfolio scope.

The owner approved all six review dimensions and both frozen semantic candidates on 2026-10-31.
The final full runner reports every EVAL-01 through EVAL-18 dimension `passed`, zero critical
failures, zero incomplete gates, and `release_gate_passed: true`. The local private-demo
configuration may therefore use semantic response-cache mode `serving` under the approved policy.

## Security, privacy, and observability impact

No credential, system prompt, full generated response, financial record, raw provider payload, or
live cache value is stored in M8 artifacts. The automated runner removes `AIFA_*`, `OPENAI_*`,
`LANGCHAIN_*`, and `LANGSMITH_*` variables before subprocesses and uses only explicit local
integration URLs for Qdrant and Redis. The separately authorized selected-model review records only
bounded counts, timings, versions, publishers/source titles, and adjudication outcomes. RunEvent
persistence stays authoritative. Collector/LangSmith failure remains isolated from product state,
and missing telemetry is represented as unavailable rather than inferred.

The threat review remains scoped to the owner-only private demo. It does not add public identity,
multi-user authorization, managed encryption/backup, audited external retention, distributed
quotas, WAF, or approved public provider rights.

## Limitations and release boundary

M8 approves the owner-only private demonstration release, not a public multi-user deployment.
Public deployment remains blocked by the production-hardening register. Monetary model cost is
still unavailable because no approved versioned provider-price calculator is configured, and
external telemetry remains optional and deployment-owned.
